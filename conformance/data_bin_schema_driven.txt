# CX Conformance — data_bin schema-driven encoding round-trips
# Version: 0.2 — 2026-05-10 (V core impl shipped in Phase 7.73)
# Covers: spec/data_bin.md §3.13, spec/decisions/0015 D3 / D4 / D5 / D6.
#
# Section types used:
#
#   schema_cxs               — schema source text
#   sd_ref_form              — "hash" | "inline" | "hash_with_name"
#                              (default "hash")
#   sd_name_hint             — name string for hash_with_name form
#   sd_assert_round_trip     — "1" asserts encode → decode succeeds
#   sd_expected_decoded_cx   — exact CX text after decode (optional;
#                              compared only when present)
#   sd_assert_flag_bit_1     — "1" asserts CXDB header flag bit 1 is set
#   sd_assert_ref_tag        — expected first byte of schema reference
#                              ("0x10" / "0x11" / "0x12")
#   sd_expected_emit_error   — expected substring of encode error message
#                              (skips round-trip if encode rejects)
#   schema_cxs_a / schema_cxs_b + sd_assert_hash_equal:
#                              hash-stability cross-check
#   in_data_bin_hex + sd_expected_decode_error:
#                              feed concrete framed bytes through the
#                              decoder and assert error
#
# Hash placeholders are NOT byte-compared. The schema content-hash is
# deterministic per ADR 0015 D5 but recomputing it on each test run
# avoids embedding a 64-character hex literal in the fixture file.
# Property tests (hash stability, ref-tag identity, flag bit identity,
# decode round-trip) cover what byte-comparison would have.

=== test: sd-004-partial-schema-open-mode-mixed-tags
level: extended
tags: data_bin schema_driven partial open_mode

# default `open` mode the encoder accepts it and emits self-describing

1
--- sd_expected_decoded_cx
[server host=localhost port=8080 region=us-west]

=== test: sd-006-hash-stable-across-source-formatting
level: extended
tags: data_bin schema_driven canonical
# Two semantically-identical schemas with different formatting (one
# with comments / extra whitespace) produce the same content-hash
# because the hash is over cx_to_data_bin(parse(schema_text)),
# not over the raw schema source.
--- schema_cxs_a
[?cx schema-of server]
[server
  [body :elem]
  [attr host :string :req]
]
--- schema_cxs_b
[?cx schema-of server]

[- a comment that does not change semantics -]
[server [body :elem] [attr host :string :req] ]
--- sd_assert_hash_equal
1

=== test: sd-009-encoding-validation-decoupled
level: extended
tags: data_bin schema_driven decoupled
# Per ADR 0015 D3, schema-driven encoding is independent of validation
# mode. A document is encoded SCHEMA-DRIVEN (flag bit 1 set) AND
# remains under `open` mode validation; an undeclared field encodes
# self-describing without producing a validation error.
--- schema_cxs
[?cx schema-of server]
[?cx schema-mode open]
[server
  [body :elem]
  [attr host :string :req]
]
--- in_cx
[server host=localhost extra=42]
--- sd_assert_flag_bit_1
1
--- sd_assert_round_trip
1
--- sd_expected_decoded_cx
[server host=localhost extra=42]

# CX Language (CXL) Conformance Suite
Version: 0.4 — 2026-05-12 (V reference evaluator rewritten under
ADR 0017 §D6/§D7 uniform directive shape per §F. Conformance fixture
runner extended in V + TypeScript with `in_cxl` / `out_text` /
`out_err` drivers; remaining bindings + native evaluators land in
follow-up phases.)

This file is the conformance home for CXL — the CX Language per
[spec/cxl.md](../spec/cxl.md), normative under [ADR 0016](../spec/decisions/0016-templates-queries-cx-expression-family.md)
with the v0.6.0 syntax rewrite per [ADR 0017](../spec/decisions/0017-collection-literals-and-cxl-refactor.md).

CXL 1.0 ships at CX release **v0.6.0** under the ADR 0017 §D7
uniform directive shape `[?Name [arg1, arg2, …]]`. The pre-0017
attribute-slot form (`:then=…/:else=…`), the `?cond` directive, the
bare positional-text form (`[?for v in expr body]`), and the
quoted-string-as-body-marker convention are dropped per §D17 — no
adopters yet, no migration required.

---

## Status at v0.6.0

- Grammar v3.6 (ADR 0017): ArgArray production [56b] forces the
  first `[…]` body item of any `[?Name …]` directive to parse as an
  Array literal. Slot bodies are CX body fragments per §D5 / §D7,
  terminating at the next depth-0 `,` `]` `)` `}`. Single-item slots
  return their lone item; multi-item slots wrap in SequenceNode.
- AST: `InterpolationNode` + `EvalDirectiveNode` carry one optional
  ArgArray (ArrayNode) child. `Attribute.body` BracketBody attribute
  values remain valid on regular Elements (no longer on EvalDirective
  attrs — §D7 drops the attribute-slot convention).
- ABI v2: `cx_eval_cxl` and `cx_eval_cxl_with_len` are fully
  implemented at the V core (`vcx/cx/cabi.v`); `cx_eval_cxl_streaming`
  returns `W012` (stub).
- Capability bits 28 (CXL) and 29 (collection literals) set in
  `cx_features`.
- The V reference evaluator (`vcx/cx/cxl.v`) implements:
  - Interpolation `[?=EXPR]` with bare-attribute (`@name`), path
    (`//service`), path-attr (`//service/@name`), and variable-
    reference (`v`, `v/@attr`) expression forms.
  - `[?if [cond, then-body, else-body?]]` two-/three-slot conditional
    (§3.2) with EBV per cxdm.md §4.5 and numeric / string / bool
    comparison ops `=`, `!=`, `<`, `<=`, `>`, `>=` per cxdm.md §8.
  - `[?if [[c1, b1], [c2, b2], [*, default]]]` multi-branch (§3.3)
    with `*` wildcard sentinel for the unconditional fallback (§D8).
  - `[?for [var, iterable, body]]` iteration with lexical scope (§3.4).
  - `[?with [context, body]]` context shift (§3.5).
  - `[?def [name, body]]` / `[?use [name, ctx?]]` named blocks
    (§3.7/§3.8).
  - Frozen filter set §4.1/4.3/4.5/4.6: `upper`, `lower`, `trim`,
    `length`, `concat`, `join`, `replace`, `default`, `first`,
    `rest`, `empty`, `reverse`, `escape-html`, `escape-url`, `raw`.
    Filter calls take an ArgArray of positional slots:
    `[?upper [@name]]`, `[?join [SEP, XS]]`. Composition by bracket
    nesting: `[?upper [[?trim [@name]]]]`.
  - Output targets: `text` (default, no auto-escape), `cx` (round-
    trip), `html` (auto-escape on `[?=…]`).
  - Top-of-file `[?cx output-target=…]` / `[?cx output-strict]`
    configuration directives (attribute-pair form retained for `?cx`
    — see §5.1 reconciliation note).
- The `.cxl` file extension is reserved per governance §12.3.

## Open gaps (CXL 1.0 not yet at full §3/§4 coverage)

- `[?include]` resolution depends on ADR 0014 include pass; pending.
- Numeric / temporal / sequence-filter completeness — `abs`, `round`,
  `format-decimal`, `format-percent`, `take`, `drop`, `distinct`,
  `where`, `format-date`, `format-datetime`, `last`, `type-of` —
  parse as EvalDirective but evaluator-side implementation pending.
- Output targets `markdown` / `json` / `yaml` / `xml` / `csv` / `tsv`
  / shape-emitter — parse-only at v0.6.0; emission per
  spec/cxl.md §6 pending.
- Whitespace-trim markers `[?-= … -]` and block-form newline
  consumption per cxl.md §2.4 — pending.
- Per-binding native evaluators (parity with V reference per ADR 0016
  D9) — pending; bindings can still call the C ABI symbols today.
- Conformance fixture runner extension — landed for V
  (`lang/v/conformance.v`) and TypeScript (`lang/typescript/conformance.ts`).
  Python / Go / Ruby / Rust / Java / Kotlin / C# / Swift runners
  still need the `in_cxl` / `out_text` / `out_err` drivers (each
  binding also needs an `eval_cxl` wrapper around the C ABI symbol).
- `[?cx [{output-target: 'html'}]]` map-arg config form (ADR 0017
  §D7 table) — parser reconciliation pending; v0.6.0 keeps the
  attribute-pair form `[?cx output-target=html]` from spec/cxl.md
  §5.1. Either the spec §5.1 attribute form is retained as the
  canonical config shape, or the parser dispatches `?cx` with a
  `[…]` body item to the new shape. Decided in §F follow-up.

## Format

Each fixture is a four-section block (one leading-equals header, an
optional metadata block, then `--- in_cxl` / `--- in_cx` / `--- out_text`
section dividers).

Error-path fixtures use `--- out_err` instead of `--- out_text`,
carrying an error-message substring that must appear in the evaluator's
returned error. CX-to-CX transformation fixtures use `--- out_cx`
carrying the expected CX output (compared after canonicalization per
spec/canonical.md).

## Categories

1. **basic** — `[?=EXPR]` interpolation, literal text, simple CXPath
2. **control-flow** — `[?if]` two-/three-slot, `[?if]` multi-branch,
   `[?for]`, `[?with]` semantics
3. **filters** — frozen built-in filter set per cxl.md §4
4. **composition** — nested directives, embedded CXPath, `[?def]` /
   `[?use]` blocks
5. **partials** — `[?include]` resolution per ADR 0014 (pending include
   resolution work)
6. **whitespace** — block-form newline rules, `[?-= ... -]` trim markers
   (pending)
7. **escaping** — target-aware auto-escape per cxl.md §6
8. **errors** — unbound variable, bad CXPath, type mismatch, recursive
   include, future-version EvalName at older evaluator, pre-0017
   syntax forms (`?cond`, `:then=…`, bare positional for)

Under the no-shortcuts v0.6.0 lock, **every** public-ABI feature ships
to all 10 bindings at v0.6.0 — there is no Tier 1 / Tier 2 / Tier 3
phasing for CXL.

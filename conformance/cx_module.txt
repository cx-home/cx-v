# cx: self-host module conformance suite
# Version: 1.0 — 2026-05-18 (DD25 per spec/v0_7_0_status.md / ADR 0023 §D7)
#
# Cross-binding byte-identity discipline. Every fixture below must
# pass byte-identical on V + Python + Go + Rust + TypeScript when each
# binding's eval_cxl wrapper routes through the shared C ABI (per EE6).
#
# Six fixture categories per ADR 0023 §D7:
#
#   1. Round-trip identity  — cx:serialize(cx:parse(t)) ≡ cx:canonical(t)
#   2. Cross-binding         — same input → same output bytes across bindings
#   3. Error path            — invalid input produces the documented CXER code
#   4. Edge cases            — empty / single / nested / anchors / IDs / IDREFs
#   5. Purity assertion      — Pure-tagged functions are repeatable on same input
#   6. Gate enforcement      — cx:eval M1..M5 mitigations (per spec/modules/cx.md §2)
#
# Naming: `cxmod-NNN-slug` where NNN is the 3-digit fixture number.
# Tags include the function row (DD1..DD22), the ADR 0023 category,
# and an optional `cross-binding` marker for fixtures specifically
# exercising the byte-identity discipline.
#
# Error-path fixtures use `--- out_err` with the cx-err:CXERNNNN
# substring; the runner does substring-match per conformance/eval.txt.
# Pure-tagged fixtures use `--- out_text` with the exact expected
# byte sequence per the V reference engine.
#
# Format per conformance/README.md. See lang/v/conformance.v for the
# in_cxl + in_cx + out_text / out_err driver.

# ── §1. cx:parse + cx:serialize + cx:canonical (DD1, DD2, DD3) ─────────

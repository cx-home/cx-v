# CX Conformance — ID/IDREF tests
# Version: 1.0 — 2026-05-08
# Covers: spec/decisions/0003-id-idref.md (ID declarations, attribute-
#         value references, CXPath [#id] predicate, round-trip).
#
# v0 scope (per ADR 0003): document-scope only. The CX → XML / JSON /
# YAML / TOML / MD round-trip mappings (D6), canonical-form ID
# renaming (D7), include-time ID merging (D3 second paragraph), and
# the [ref @id] body-position node form (D1 second bullet) are
# deferred to follow-up phases.
#
# Verification: parse `in_cx`, re-emit through emit_cx, compare
# against `out_cx`. Mismatch on parse OR mismatch on round-trip
# fails.

=== test: id-015-canonical-renames-in-document-order
level: core
tags: identity canonical
# ADR 0003 D7: strict canonical rewrites IDs to id-N in document
# order, and rewrites references to track the renamed declarations.
# Two documents differing only in ID spelling produce byte-identical
# canonical output.
--- in_cx
[users
  [user #alice name=Alice]
  [user #bob name=Bob]
  [reviewer assigned-to=@alice]
  [reviewer assigned-to=@bob]
]
--- out_canonical
[users
  [user #id-1 name=Alice]
  [user #id-2 name=Bob]
  [reviewer assigned-to=@id-1]
  [reviewer assigned-to=@id-2]
]

=== test: id-016-canonical-spelling-independent-hash
level: core

=== test: id-017-canonical-forward-reference-renamed
level: core
tags: identity canonical forward
# Forward reference: @target appears before #target in source order.
# Renaming visits #target on the second pass; the forward @target
# reference picks up the same id-1 name.
--- in_cx
[doc
  [pointer to=@target]
  [thing #target value=42]
]
--- out_canonical
[doc
  [pointer to=@id-1]
  [thing #id-1 value=42]
]

=== test: id-018-body-position-ref-round-trips
level: core
tags: identity reference body-position
# ADR 0003 D1 second bullet: `[ref @id]` body-position node form.
# Element named `ref` with body of exactly a single `@name` token
# is a syntactic reference, not a regular text-body element.
--- in_cx
[doc
  [thing #t-1 v=42]
  [para See [ref @t-1] for details.]
]
--- out_cx
[doc
  [thing #t-1 v=42]
  [para 'See ' [ref @t-1] ' for details.']
]

=== test: id-020-body-position-ref-non-conforming-rejected
level: core
tags: identity reference body-position strict-reservation GG12
# v0.7.0 (GG12 / ADR 0003 D1 strict): elements named `ref` whose body
# is NOT exactly `@<Name>` are now a parse error. v0.6.0 admitted
# them as regular elements for back-compat; v0.7.0 tightens to the
# spec's reserved-name commitment. Migration: rename to a non-
# reserved element name or use `cx upgrade-config` (status row I1)
# to mechanize the fix. See `docs/migrations/v0.6-to-v0.7.md §M7`.
--- in_cx
[doc [ref note=hi]]
--- out_err
E207

=== test: id-021-body-ref-xml-emits-cx-body-ref-attribute
level: core
tags: identity reference body-position xml round-trip
# Per ADR 0003 D1 second bullet (GG7 row at spec/v0_7_0_status.md):
# the `[ref @id]` body-position form round-trips through XML as the
# `cx:body-ref="<id>"` attribute. xml:id carries the declaration
# side; cx:body-ref carries the reference side.
--- in_cx
[doc
  [section #s-1
    [title Intro]
  ]
  [para See [ref @s-1] for context.]
]
--- out_xml
<doc>
  <section xml:id="s-1">
    <title>Intro</title>
  </section>
  <para>See <ref cx:body-ref="s-1"/> for context.</para>
</doc>

=== test: id-022-body-ref-xml-import-reconstructs-body-position-form

=== test: id-023-body-ref-json-semantic-emit
level: extended
tags: identity reference body-position json semantic
# Per spec/conversions.md §1.1 (GG8 row): body-position [ref @id]
# projects to JSON's `{"$ref": "<id>"}` shape in semantic-emit. This
# matches the JSON Pointer convention and gives YAML/TOML/MD a
# cross-format consensus shape.
--- in_cx
[doc [section #s-1 [title T]] [para [ref @s-1]]]
--- out_json
{
  "doc": {
    "section": {
      "title": "T"
    },
    "para": {
      "ref": {
        "$ref": "s-1"
      }
    }
  }
}

# Schema validator conformance suite — Phase 7.74c-schema-validator-v-core
# (ADR 0009 + spec/schema.md §10).
#
# v0.6.0 bootstrap covers four rules end-to-end (S002 missing required
# attr, S003 / S004 cardinality, S005 type mismatch, S017 root
# mismatch). Stubs exist in vcx/cx/schema_validate.v for the remaining
# ten rules; their fixtures land alongside the implementations in
# Phase 7.74d.
#
# Section types:
#   in_cx          — target document
#   schema_cxs     — schema source (.cxs)
#   sv_assert_valid           — '1' to assert zero error diagnostics
#                               (warnings / info do NOT invalidate)
#   sv_expected_codes         — comma-separated error-severity codes
#                               (S002,S003,...) in document order
#   sv_expected_warn_codes    — comma-separated warn-severity codes
#                               (Phase 7.74d: strict-mode S001/S012)
#   sv_expected_info_codes    — comma-separated info-severity codes
#                               (reserved)
# Failure if codes don't match exactly. The runner only inspects codes,
# not messages.

=== test: sv-056 GG10 body :ref accepts ref element with body-position form
level: must
tags: schema S023 body-ref GG10

# v0.7.0 GG10 (ADR 0003 D1 second bullet): `[body :ref]` declares
# the target element MUST carry the body-position reference form
# (Element.body_ref set, items empty). The parser lifts body_ref
# only for elements named `ref` per the GG12 strict reservation;
# this fixture pairs an authored `[ref @s-1]` with a schema that

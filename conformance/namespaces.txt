# CX Conformance — Namespace Tests
# Version: 1.0 — 2026-05-08
# Covers: ADR 0002 — XML-style scoped namespaces.
#   - Prefix declarations (xmlns:foo=URI)
#   - Default-namespace declarations (xmlns=URI)
#   - Prefix scoping and redeclaration
#   - CX ↔ XML round-trip preserving xmlns declarations
#   - Reserved xml:/cx: prefixes
#
# Verification is via behavior: input CX is reparsed, then re-emitted
# to CX and to XML. Mismatch on either output fails the test. The
# resolve_namespaces() post-parse pass populates Element.ns_uri /
# Attribute.ns_uri internally; those are not currently exposed in the
# AST-JSON wire shape (deliberate — internal resolution detail).

=== test: ns-001-default-declaration
level: core
tags: namespaces default
--- in_cx
[doc xmlns=urn:example
  [item value=42]
]
--- out_xml
<doc xmlns="urn:example">
  <item value="42"/>
</doc>
--- out_cx
[doc xmlns=urn:example
  [item value=42]
]

=== test: ns-013-canonical-prefix-rewrite
level: core
tags: namespaces canonical D6
# Two prefixes alias the same URI (urn:x). The lex-smallest prefix
# `a` wins as the canonical choice, so usage of `b:item` and
# attribute `b:tag=...` rewrites to the `a:` form. The xmlns
# declarations themselves are preserved (sorted) — only usage sites
# are rewritten.
--- in_cx
[root xmlns:b=urn:x xmlns:a=urn:x
  [b:item b:tag=value body]
]
--- out_canonical
[root xmlns:a=urn:x xmlns:b=urn:x
  [a:item a:tag=value body]
]

=== test: ns-014-canonical-xmlns-sort
level: core
tags: namespaces canonical declaration-order
# Source order of xmlns declarations is preserved by `cx fmt`
# (lossless) but strict canonical sorts them: default-ns first,
# then alphabetical by prefix. Non-xmlns attributes keep their
# source order, after the sorted xmlns block.
--- in_cx
[root xmlns:zeta=urn:z xmlns=urn:default xmlns:alpha=urn:a id=42 lang=en
  [child]
]
--- out_canonical
[root xmlns=urn:default xmlns:alpha=urn:a xmlns:zeta=urn:z id=42 lang=en
  [child]
]

=== test: ns-015-canonical-equiv-different-prefixes
level: core
tags: namespaces canonical equivalence
# Two equivalent documents — same expanded names, different prefix
# choices — produce identical strict-canonical output, which is the
# property `cx hash` and `cx eq` rely on.
--- in_cx
[svg xmlns:s=http://www.w3.org/2000/svg
  [s:circle s:r=10]
]
--- out_canonical
[svg xmlns:s=http://www.w3.org/2000/svg
  [s:circle s:r=10]
]

=== test: ns-016-canonical-reserved-prefix
level: core
tags: namespaces canonical reserved
# Reserved `xml:` prefix never appears as an xmlns declaration even
# under canonical form; usage of `xml:base` stays on `xml:` since
# that is the lex-smallest (and only) prefix mapping to the XML
# built-in URI.
--- in_cx
[doc xml:base=https://example.com xml:id=root content]
--- out_canonical
[doc xml:base=https://example.com xml:id=root content]

1. Typed round-trip: integers stay integers across format hops
─────────────────────────────────────────────────────────────────

 CX source:
 [config
  [port::u16 8080]
  [user_id::i64 9007199254740993]
  [pi::f64 3.141592653589793]
 ]

 Converted to JSON (cx --from=cx --to=json):
 {
   "config": {
     "port": 8080,
     "user_id": 9007199254740993,
     "pi": 3.141592653589793e0
   }
 }

 JSON would silently float 9007199254740993 → 9007199254740992
 in JavaScript / browsers / many parsers. CX/CXCol preserves
 int64 exactly. This is the type-fidelity contract that makes
 CX an honest source-of-truth format.

2. [table[…]] — tabular data as a first-class shape (CSV round-trippable)
─────────────────────────────────────────────────────────────────

 CX source:
 [users [table[name age::int city]]
  alice 30 portland
  bob 25 austin
  carol 40 lisbon
 ]

 Converted to CSV (cx --csv — RFC 4180):
 name,age,city
 alice,30,portland
 bob,25,austin
 carol,40,lisbon

3. CX code — programs share the data syntax, one parser, one model
─────────────────────────────────────────────────────────────────

 Program:
 [?let [= $name erik] [= $verbose true]
  [greeting [?if $verbose
    [then [?str 'Hello, {$name}!']]
    [else [?str 'Hello, friend!']]]]]

 Evaluates to: [greeting 'Hello, erik!']
 (Run any file the same way: cx program.cx — or pipe one in:
 cat data.cx program.cx | cx)

4. Why CX over JSON / YAML / TOML?
─────────────────────────────────────────────────────────────────

 | feature | JSON | YAML | TOML | CX |
 |----------------------------------|------|------|------|----|
 | Comments | - | ✓ | ✓ | ✓ |
 | Sized integer types | - | - | - | ✓ |
 | int64 / bigint precision | - | ✓ | ✓ | ✓ |
 | One syntax for data + docs | - | - | - | ✓ |
 | Canonical hash for content addr | - | - | - | ✓ |
 | Tabular `[table[…]]` block | - | - | - | ✓ |
 | logfmt mode (top-level kv) | - | - | - | ✓ |
 | Lossless round-trip to all 5 | - | - | - | ✓ |
